Asynchronous JavaScript Tutorial        

Mastering Asynchronous JavaScript

   

JavaScript is single-threaded, meaning it can only do one thing at a time. To prevent long-running tasks (like fetching data from a server) from freezing the entire application, JavaScript uses asynchronous programming.

   
       

1. Callbacks

       

A callback is a function passed as an argument to another function, which gets executed after the primary operation completes. This was the original way to handle async operations in JavaScript.

        
function fetchData(callback) {
    setTimeout(() => {
        const data = { user: "Alice", role: "Admin" };
        callback(data); // Executed after 1 second
    }, 1000);
}

// Using the callback
fetchData((result) => {
    console.log("Data received:", result);
});
       

Warning: Nesting too many callbacks leads to "Callback Hell," making code hard to read and maintain.

   
   
       

2. new Promise

       

A Promise represents the eventual completion (or failure) of an asynchronous operation and its resulting value. It has three states: Pending, Fulfilled, or Rejected.

        
const checkWeather = new Promise((resolve, reject) => {
    let isRaining = false;
    
    setTimeout(() => {
        if (isRaining) {
            reject("Picnic cancelled, it's raining.");
        } else {
            resolve("Sunny day, let's go!");
        }
    }, 1000);
});

// Consuming the promise
checkWeather
    .then(message => console.log(message))
    .catch(error => console.error(error));
   
   
       

3. async / await

       

Introduced in ES8, async/await is syntactic sugar on top of Promises. It allows you to write asynchronous code that looks and behaves like synchronous code, making it much easier to read.

       
               
  • async: Makes a function return a Promise automatically.
    •            
  • await: Pauses the execution of the async function until the Promise resolves or rejects.
    •        
        
const getUserProfile = () => {
    return new Promise(resolve => setTimeout(() => resolve({ id: 1 }), 1000));
};

async function displayUser() {
    try {
        console.log("Fetching...");
        const user = await getUserProfile(); // Waits here for 1 second
        console.log("User loaded:", user);
    } catch (error) {
        console.error("Failed to load user:", error);
    }
}

displayUser();
   
   
       

4. Promise.all

       

Promise.all takes an array of Promises and executes them concurrently. It waits for all of them to resolve. If even one Promise rejects, the entire Promise.all immediately rejects.

        
const fetchUsers = new Promise(resolve => setTimeout(() => resolve("Users"), 1000));
const fetchPosts = new Promise(resolve => setTimeout(() => resolve("Posts"), 1500));

async function loadDashboard() {
    console.time("Dashboard Load");
    // Both start at the same time, takes ~1.5s total (the longest wait)
    const [users, posts] = await Promise.all([fetchUsers, fetchPosts]);
    
    console.log(users, posts);
    console.timeEnd("Dashboard Load");
}

loadDashboard();
   
   
       

5. Promise.race

       

Promise.race also takes an array of Promises, but it only waits for the first Promise to settle (either resolve or reject). Once the fastest Promise finishes, it ignores the rest.

        
const slowQuery = new Promise(resolve => setTimeout(() => resolve("Slow database data"), 3000));
const timeout = new Promise((_, reject) => setTimeout(() => reject("Request timed out!"), 2000));

async function fetchWithTimeout() {
    try {
        // The timeout will win this race, causing an error
        const result = await Promise.race([slowQuery, timeout]);
        console.log(result);
    } catch (error) {
        console.error(error); // Logs: "Request timed out!"
    }
}

fetchWithTimeout();
